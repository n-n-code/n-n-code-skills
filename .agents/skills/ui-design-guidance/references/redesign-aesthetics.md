# Redesign Aesthetic Direction

Read this reference only when a UI implementation explicitly needs a new or
substantially stronger visual direction. Do not load it for routine UI changes,
preserve-mode work, or review-only tasks whose main need is accessibility or
interaction evidence.

## Direction prompts

- Choose typography intentionally within the product, brand, localization, and
  repository constraints. A familiar stack is appropriate when consistency or
  performance matters more than novelty.
- Use a cohesive palette and reusable semantic tokens instead of scattered
  one-off colors.
- Use motion deliberately. Prefer a few transitions that explain state or
  hierarchy, and preserve reduced-motion behavior.
- Add texture, layering, contrast, shadows, or pattern only when they support
  the chosen tone and content hierarchy.
- Avoid unexamined defaults that make unrelated products look interchangeable;
  distinctiveness should come from the product's purpose rather than novelty
  for its own sake.
- Keep visual choices consistent across the whole surface so the result feels
  designed rather than decorated.

Treat these as prompts, not mandatory style rules. User requirements, product
semantics, accessibility, and the repository's established design system take
precedence.
